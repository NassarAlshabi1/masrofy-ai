# مصروفي — مثال تعليمي لبناء APK

قالب ويب عربي بسيط يوضح تحويل HTML وJavaScript إلى تطبيق Android باستخدام Capacitor وGitHub Actions، دون تثبيت Android Studio.

## ما يعمل الآن
- تسجيل مصروف بوصف ومبلغ صحيح واحد **بدون كسور** (أرقام صحيحة فقط)، مع دعم الأرقام العربية والفارسية وفواصل الآلاف مثل 1,200.
- **لا تظهر أي عملة في الواجهة**: لا جنيه ولا ريال ولا USD؛ المبالغ تُعرض كأرقام مجردة فقط، وإذا كتبت اسم عملة في المدخل (جنيه، ريال، دولار، usd...) يُحذف تلقائيًا من الوصف.
- حفظ المصروفات وحالة مهمتين تجريبيتين محليًا في `localStorage` واسترجاعها بعد إعادة التحميل، مع ترقية تلقائية للبيانات القديمة المكتوبة بالقروش إلى مبالغ صحيحة.
- حساب الإجمالي والمتبقي من ميزانية تجريبية ثابتة قدرها 8000 (بدون رمز عملة) وإظهار التجاوز.
- فلترة بسيطة للمشتريات والفواتير بكلمات مفتاحية، **وليست نموذج AI**.
- جميع ملفات العرض ضمن `www`؛ لا يحتاج APK اتصالًا لعرض الواجهة أو تسجيل المصروفات.

مثال: `قهوة ٦٥` أو `فاتورة 1,200`. أي مدخل يحتوي كسورًا عشرية (مثل 65.50) يُرفض برسالة واضحة ولا يتم مسح المدخل.

## حدود المثال
هذا ليس تطبيقًا ماليًا للإنتاج: لا مزامنة سحابية أو ذكاء اصطناعي أو تسجيل صوتي أو حسابات مستخدمين أو تحليلات. الأزرار غير المنفذة معطلة بوضوح. الأسماء والمهام والميزانية عناصر تعليمية. حفظ البيانات محلي وليس نسخة احتياطية أو تخزينًا مشفرًا؛ حذف التطبيق/مسح بياناته قد يمسح السجل. لا تدخل معلومات مالية حساسة. لا تستخدم هذا المثال كسجل محاسبي.

حُوّلت الخطوط والأيقونات الخارجية إلى خطوط النظام ورموز محلية حتى يعمل أول تشغيل دون إنترنت؛ لذلك قد تختلف هيئة الرموز بين الأجهزة. تشغيل نسخة الويب لأول مرة يحتاج تحميل ملفاتها، ولا توجد Service Worker لتثبيت نسخة PWA أوفلاين؛ ضمان تضمين الملفات هنا خاص بالـAPK.

## التشغيل والاختبار
```sh
npm ci
npm test
npm run build:css
```
اعرض مجلد `www` باستخدام خادم محلي بسيط مثل `python -m http.server 8000 --directory www`، ثم افتح `http://localhost:8000`.

الكود الرئيسي: `www/model.js` لتحليل المبالغ الصحيحة والتحقق والترحيل، و`www/app.js` للحفظ والعرض. التصميم في `www/index.html` و`tailwind.config.js`. عند تعديل CSS شغّل `npm run build:css` واحفظ الناتج `www/styles.css`.

## إنشاء APK (إصدار Release موقّع — ليس لـ Google Play)
فرع `no-fractions-no-currency` يحتوي Workflow **Build Release APK (Signed, Not for Google Play)** في `.github/workflows/build-release-apk.yml`، يعمل تلقائيًا مع كل دفع إلى الفرع أو يدويًا من تبويب Actions. الناتج **Release APK موقّع** جاهز للتثبيت المباشر (sideload) على أي هاتف Android، وليس إصدار متجر.

- التوقيع بمفتاح self-signed ثابت محفوظ في `signing/masrofy-release.keystore` (كلمة المرور في متغيرات بيئة خطوة البناء)، لذلك التحديثات اللاحقة تُثبَّت فوق النسخة السابقة دون إلغاء التثبيت.
- لأن المشروع **ليس لـ Google Play**، حفظ مفتاح التوقيع داخل المستودع مقبول هنا؛ لا تستخدم هذا المفتاح لأي تطبيق متجر.
- البناء يحتاج الإنترنت، أما تشغيل ملفات التطبيق المضمّنة فلا يحتاجه. لا تَعِد بمدة بناء محددة: تختلف حسب GitHub Actions والشبكة.
- يوجد أيضًا Workflow قديم يبني Debug APK (`build-apk.yml`) يعمل على `main` فقط.

بعد البناء اختبر على هاتف فعلي: أضف مصروفًا بمبلغ صحيح، أغلق التطبيق بالكامل ثم افتحه، ثم كرر مع وضع الطيران من أول تشغيل. اختبارات المستودع تتحقق من منطق البيانات وبنية DOM ورفض الكسور وغياب رمز العملة، لكنها لا تغني عن اختبار Android فعلي.
